CloudVPN+ Admin Portal Documentation
Comprehensive Architectural Overview, System Structure & Technical Specifications

1. Executive Summary & Project Objectives

The CloudVPN+ Admin Portal is a pure-frontend administration system designed to integrate directly with an unmodified ccserver.py FastAPI backend. The portal provides identity verification, cryptographic handshake authentication, real-time VPN routing server management, paginated user account management, quota control, and live query diagnostics.

The user interface follows a light-theme frosted glassmorphism design language overlaid on a nature background image. All styling adheres strictly to architectural rules: no color gradients, no shades of purple, blue, or pink, and no emojis.

4. Cryptographic Authentication & Nonce Protocol

To prevent replay attacks and secure administrative operations without modifying ccserver.py, every administrative route in ccserver.py requires a dynamic hashed password computed using a single-use server nonce:

  1. Admin Nonce Fetch: The client sends an HTTP GET request to /admin/nonce with payload {"UEmail": email} using XMLHttpRequest.
  2. Nonce Increment: ccserver.py executes db["admins"][email]["nonce"] += 1 and returns {"nonce": new_nonce}.
  3. SHA-256 Hashing: The client computes sha256(actualPassword + String(nonce)) via sha256.js.
  4. Target Endpoint Execution: The client issues the final administrative GET request containing the hashed token in the URL path.
  5. Server Verification: ccserver.py calls verifynonce(email, "password", passwd, role="admins"), comparing the received token against hashlib.sha256((db["admins"][email]["password"] + str(db["admins"][email]["nonce"])).encode("utf-8")).hexdigest().

5. Pure JavaScript Cryptography & HTTP Compatibility

Browsers enforce security restrictions that disable window.crypto.subtle on non-HTTPS origins (except localhost). Because the portal must be hostable over plain HTTP without HTTPS dependencies, sha256.js implements the complete NIST FIPS 180-4 SHA-256 specification in pure JavaScript:

  • Manual UTF-8 encoding support handling all single-byte, multi-byte, and surrogate pair characters.
  • 64-round compression engine using 32-bit bitwise unsigned integer operations (>>>).
  • Deterministic zero-padded 64-character hexadecimal digest output matching Python hashlib.sha256 byte-for-byte.

6. Dynamic Base URL Architecture

The portal does not hardcode any server domain or port. In admin_api.js, getBaseUrl() dynamically parses window.location.origin (or combines window.location.protocol and window.location.host). Administrators can also set a custom Base URL in the dashboard settings modal, which is persisted in sessionStorage.
