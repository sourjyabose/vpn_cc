File Documentation: admin_dashboard.html

Admin Dashboard & Control Center Interface Specification

First: Necessity, Role, and Project Interaction

Why this file is necessary: admin_dashboard.html serves as the primary operational workspace for CloudVPN+ administrators. It exposes intuitive, real-time controls for all administrative endpoints in ccserver.py, enabling cluster node orchestration, user management, bandwidth monitoring, account blocking/unblocking, and diagnostic queries.

How it fits into the project: It provides the UI canvas onto which admin_dashboard.js binds event listeners, renders tables, injects stat counters, and manages modal workflows.

How it interacts with the project:

  • Imports css/admin_style.css for modular glassmorphic layout and theme styling.
  • Imports js/sha256.js, js/admin_api.js, js/admin_auth.js, and js/admin_dashboard.js to initialize the reactive controller upon load.
  • Renders responsive views across multiple tab panes (Overview, Users, Servers, Diagnostics) and dialog modals.

Second: Overall Project Structure & Architectural Context

Third: Detailed Breakdown of Structural Sections & Elements

1. Top Navbar Header (<header class="glass-panel top-navbar">)

  • #btnOpenBaseUrlModal: Button displaying current origin and opening the base URL configuration modal.
  • #currentBaseUrlText: Text container showing the active base URL (e.g. http://localhost:8000).
  • #currentAdminEmail: Text badge showing authenticated administrator identity (e.g. root).
  • #btnLogout: Button bound to AdminAuth.logout().

2. Sidebar Navigation (<aside class="glass-panel dashboard-sidebar">)

  • button[data-tab-target="overview"]: Activates the fleet overview pane.
  • button[data-tab-target="users"]: Activates the user directory and pagination pane.
  • button[data-tab-target="servers"]: Activates the server registry pane.
  • button[data-tab-target="diagnostics"]: Activates the live query console pane.

3. Overview & Fleet Pane (#tab-overview)

  • #statTotalServers: Displays total registered servers count.
  • #statTotalUsers: Displays total user accounts count.
  • #statActiveUsers: Displays active (unblocked) user accounts count.
  • #statBlockedUsers: Displays blocked accounts count.
  • #statTotalBandwidth: Displays aggregate bandwidth used formatted in MB/GB.
  • #overviewServersList: Dynamic card grid showing registered servers with online status.
  • #formSearchUser & #searchUserEmail: Quick lookup form calling CloudVPNDashboard.inspectUser().

4. User Directory Pane (#tab-users)

  • #usersTableBody: Table body rendered with user email, nonce, device ID, quota, usage, status, and action buttons.
  • #userPaginationInfo: Displays current slice range (e.g. 0 - 20).
  • #btnPrevUserPage & #btnNextUserPage: Pagination step buttons.

5. Server Registry Pane (#tab-servers)

  • #serversTableBody: Table listing server names with deregistration actions.
  • #btnOpenRegisterServer: Triggers server registration modal.

6. Live Diagnostics Pane (#tab-diagnostics)

  • #diagEndpointSelect: Dropdown to select target administrative endpoint.
  • #diagParamInput: Text input for route parameters.
  • #btnRunDiagnostic: Executes query with fresh nonce.
  • #diagResultBox: Formatted JSON response viewer.

7. Modals & Toasts

  • #modalRegisterServer: Modal dialog for registering a new server node (inputs: #regServerName, #regServerKey).
  • #modalChangeEmail: Modal dialog for changing user email (inputs: #changeEmailOld, #changeEmailNew).
  • #modalInspectUser: Modal dialog rendering full user data and raw JSON.
  • #modalConfirm: Reusable confirmation dialog for dangerous actions (remove server, delete user).
  • #modalBaseUrl: Configuration modal for setting a custom backend origin.
  • #toastContainer: Absolute-positioned container for floating alert notifications.

8. Script Dependencies

  • imported sha256 from js/sha256.js (Pure JS hashing).
  • imported CloudVPNApi from js/admin_api.js (API client).
  • imported AdminAuth from js/admin_auth.js (Session authentication guard).
  • imported CloudVPNDashboard from js/admin_dashboard.js (Dashboard logic controller).
