File Documentation: admin_auth.js

Admin Authentication & Session Management Specification

First: Necessity, Role, and Project Interaction

Why this file is necessary: admin_auth.js provides administrative identity validation rules, session storage lifecycle controls, and route protection guards. It enforces the specific requirement that the username root is accepted directly without requiring email formatting, while all other identities must adhere to valid RFC email structures.

How it fits into the project: It sits between the user interface views (admin_login.html, admin_dashboard.html, index.html) and the communication client (admin_api.js). It prevents unauthorized access to the dashboard by enforcing authentication checks.

How it interacts with the project:

  • Imports CloudVPNApi from js/admin_api.js to invoke verifyLogin().
  • Utilized by admin_login.html to validate inputs and authenticate.
  • Utilized by admin_dashboard.html to enforce AdminAuth.requireAuth() on initialization and handle user logout.
  • Utilized by index.html to evaluate whether to direct traffic to the login screen or dashboard.

Third: Detailed Breakdown of Functions and Members in AdminAuth

1. Property: STORAGE_KEY

  • Type: string (Value: 'cloudvpn_admin_session')
  • Purpose: Standardized key used to store and retrieve administrative session tokens in the browser's sessionStorage.

2. validateAdminIdentity(input)

  • Purpose: Validates user identity input. If the input is "root" (case-insensitive), it is immediately marked valid. If not "root", it is validated against RFC 5322 email regular expression: 
    /^[a-zA-Z0-9.!#$%&'*+/=?^_`{|}~-]+@[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?(?:\.[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?)+$/
  • Data Types:
    • input (string): Identity string from login form.
    • Returns: { isValid: boolean, message: string }

3. validatePassword(password)

  • Purpose: Validates that the master password input is non-empty.
  • Data Types: password (string). Returns { isValid: boolean, message: string }.

4. getSession()

  • Purpose: Parses and returns the active session object from sessionStorage.
  • Data Types: Takes no arguments. Returns { email: string, password: string, loggedInAt: string } | null.

5. saveSession(email, password)

  • Purpose: Serializes administrator credentials and login timestamp into sessionStorage.
  • Data Types: email (string), password (string). Returns void.

6. clearSession()

  • Purpose: Deletes cloudvpn_admin_session from sessionStorage.
  • Data Types: Returns void.

7. login(identity, password)

  • Purpose: Validates input fields, calls CloudVPNApi.verifyLogin(), saves session on success, or returns error message.
  • Data Types: identity (string), password (string). Returns Promise<{ success: boolean, message?: string }>.
  • Imported Dependencies: imported CloudVPNApi from js/admin_api.js (Invokes verifyLogin).

8. logout()

  • Purpose: Clears session and redirects the window to admin_login.html.
  • Data Types: Returns void.

9. requireAuth()

  • Purpose: Route guard that checks if an active session exists. If missing, forces immediate redirection to admin_login.html.
  • Data Types: Returns { email: string, password: string } | null.
