Controller Specification

File Documentation: auth_js.html

Target File: js/auth.js | Type: ECMAScript 6 Authentication Controller

First: Purpose, Necessity & Project Fit

Why this file is necessary: auth.js is the primary user interaction controller for credential onboarding and verification. It binds event listeners to the DOM forms on both signup.html and login.html, conducts live validation, coordinates network submissions, and implements the required global window.login_succ() callback.

How it fits into the project: It drives the logic for registration and sign-in experiences, bridging UI inputs with the validation and API services.

How it interacts with the project:

  • Reads inputs from DOM elements defined in signup.html and login.html.
  • Invokes static methods from FormValidator (in validation.js).
  • Dispatches asynchronous authentication payloads through CloudVPNAPI (in api_client.js).
  • Executes window.login_succ() to smoothly navigate authenticated users to recharge.html.

Second: Project Structure, Architecture & Design Rationale

Architecture & Design Rationale: Uses defensive event listener registration. It checks for the existence of #signupForm or #loginForm before executing page-specific logic, allowing a single unified script to serve both pages without errors.

Imported Dependencies:

  • imported FormValidator from validation.js (reason: required to validate email format, password complexity, and password equality).
  • imported CloudVPNAPI from api_client.js (reason: required to dispatch async HTTP requests and manage session storage).

Functions & Global Handlers

Function Name Parameters Return Type Comprehensive Specification
window.login_succ(userData) userData: object (e.g. { token: string, user: object }) void What it does: Core function called upon successful authentication. Logs execution to console, renders a success notification banner (#alertBanner) in the frosted glass card, caches the user session in storage, and executes a smooth 800ms delayed redirect to recharge.html.
Why needed: Directly fulfills the user requirement: "after succeful login (which will be indicated when I run call login_succ())".
Interactions: Imported/called by login form submit handler and accessible globally via console/script.
DOMContentLoaded Listener event: Event void What it does: Initializes DOM bindings for password show/hide buttons, real-time input event listeners, and form submit handlers.
