Module Specification

File Documentation: validation_js.html

Target File: js/validation.js | Type: ECMAScript 6 Vanilla JavaScript Module

First: Purpose, Necessity & Project Fit

Why this file is necessary: validation.js enforces strict client-side data hygiene and user experience feedback. It guarantees that malformed emails, weak passwords, and mismatched confirmation inputs are detected instantly in real-time before network requests are ever triggered.

How it fits into the project: It acts as a shared utility imported by both signup.html and login.html, providing a single source of truth for all validation rules.

How it interacts with the project:

  • Exposes the global static class FormValidator on the window object.
  • Invoked by auth.js inside DOM event listeners (input, change, submit).
  • Manipulates DOM class lists (.is-valid, .is-invalid) styled by style.css.

Second: Project Structure, Architecture & Design Rationale

Architecture & Design Rationale: Implemented as a purely stateless static class (FormValidator). By avoiding instance state, methods are pure functions that take inputs and return deterministic result objects ({ isValid: boolean, message: string }), maximizing testability and preventing memory leaks.

RFC 5322 Standard Email Pattern: Employs the industry-standard regex /^[a-zA-Z0-9.!#$%&'*+/=?^_`{|}~-]+@[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?(?:\.[a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?)+$/ to validate email strings accurately without false positives.

Third: Exhaustive Class & Method Documentation

Class: FormValidator

Scope: Global (attached to window.FormValidator)
Description: Static utility class for form validation and DOM feedback manipulation.

Method Name Parameters Return Type Comprehensive Specification
validateEmail(email) email: string { isValid: boolean, message: string } What it does: Trims whitespace, checks for non-empty string, executes RFC 5322 regex test, checks max length limit (254 chars).
Why needed: Prevents malformed emails from reaching backend authentication endpoints.
Interactions: Called by auth.js on #signupEmail and #loginEmail input events.
validatePassword(password) password: string { isValid: boolean, message: string, score: number } What it does: Validates length (8 to 128 chars), checks for presence of both letters and numbers, calculates strength score.
Why needed: Ensures user accounts are secured with strong credentials.
Interactions: Called on #signupPassword in signup.html.
validatePasswordMatch(password, reenterPassword) password: string,
reenterPassword: string		 { isValid: boolean, message: string } What it does: Compares the confirmation password against the primary password for strict equality (password === reenterPassword).
Why needed: Prevents typo errors when setting passwords.
Interactions: Called on #signupReenterPassword in signup.html.

feedbackEl: HTMLElement,
isValid: boolean,
